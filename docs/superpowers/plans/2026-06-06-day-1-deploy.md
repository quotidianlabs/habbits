# Day-1 Deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a live `https://habbits.fly.dev/healthz → 200 OK {"status":"ok"}` served through panic-recovery → request-id → slog middleware, deployed by GHA on every merge to `main`, with a single Go integration test verifying the chain in PR CI.

**Architecture:** Go binary using `net/http` + `chi`. Project layout: `cmd/server/main.go` for the entrypoint, `internal/server/` for the chi router + `/healthz` handler, `internal/middleware/` for the three middlewares. Module name is `habbits` (no domain prefix; can be renamed later if needed). Deploy artifact is a multi-stage Docker image built by Fly from a `fly launch`-generated Dockerfile.

**Tech Stack:** Go 1.23+, `github.com/go-chi/chi/v5`, `log/slog` (stdlib), `github.com/google/uuid` for request IDs. Fly.io for hosting (`*.fly.dev`, auto-TLS). GitHub Actions for CI/CD using `superfly/flyctl-actions/setup-flyctl@master`.

**Source design:** `docs/superpowers/specs/2026-06-06-day-1-deploy-design.md`. Foundation: `docs/superpowers/specs/2026-06-05-habbits-foundation.md`.

**Pre-flight (developer, not the agent):** flyctl installed and logged in (`fly auth whoami` shows your user). GitHub `gh` CLI installed and authenticated (`gh auth status` clean). A Fly region preference chosen (e.g. `iad`, `lhr`, `fra`, `syd`) — controller will surface this before Task 8.

### Task 4: Implement Request-ID middleware

**Files:**
- Create: `internal/middleware/requestid.go`
- Modify: `internal/server/server.go`

This task makes the integration test fully pass.

- [ ] **Step 1: Create `internal/middleware/requestid.go`**

```go
package middleware

import (
	"context"
	"net/http"

	"github.com/google/uuid"
)

type ctxKey int

const requestIDKey ctxKey = 0

// HeaderRequestID is the response and (optional) request header name.
const HeaderRequestID = "X-Request-ID"

// RequestID generates a UUID for each request, stores it on the context,
// and sets the response header.
func RequestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := uuid.NewString()
		ctx := context.WithValue(r.Context(), requestIDKey, id)
		w.Header().Set(HeaderRequestID, id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

// GetRequestID returns the request ID from context, or "" if absent.
func GetRequestID(ctx context.Context) string {
	if v, ok := ctx.Value(requestIDKey).(string); ok {
		return v
	}
	return ""
}
```

### Task 5: Implement Recoverer middleware

**Files:**
- Create: `internal/middleware/recover.go`
- Modify: `internal/server/server.go`

Recoverer must be registered BEFORE RequestID in `r.Use` order so it wraps everything (including RequestID itself — a panic during ID generation must not crash the process). Recoverer reads the request ID from context if available (it usually won't be present for a panic that fires before RequestID runs; that's fine, it logs `""`).

- [ ] **Step 1: Create `internal/middleware/recover.go`**

```go
package middleware

import (
	"log/slog"
	"net/http"
	"runtime/debug"
)

// Recoverer catches panics in downstream handlers, logs the stack trace
// with the request ID (if available), and responds with 500.
func Recoverer(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rv := recover(); rv != nil {
				slog.Error("panic in handler",
					slog.String("request_id", GetRequestID(r.Context())),
					slog.Any("panic", rv),
					slog.String("stack", string(debug.Stack())),
				)
				http.Error(w, "Internal Server Error", http.StatusInternalServerError)
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

- [ ] **Step 2: Wire Recoverer as the outermost middleware in `server.go`**

Update `internal/server/server.go`:

### Task 6: Implement SlogLogger middleware

**Files:**
- Create: `internal/middleware/slog.go`
- Modify: `internal/server/server.go`

SlogLogger is the innermost middleware: registered AFTER RequestID so it sees the request ID in context. Per-request log line has method, path, status, duration_ms, request_id.

- [ ] **Step 1: Create `internal/middleware/slog.go`**

```go
package middleware

import (
	"log/slog"
	"net/http"
	"time"
)

// statusRecorder captures the status code written by the handler so it can be logged.
type statusRecorder struct {
	http.ResponseWriter
	status int
}

func (s *statusRecorder) WriteHeader(code int) {
	s.status = code
	s.ResponseWriter.WriteHeader(code)
}

// SlogLogger emits one structured log line per request including method,
// path, status, duration, and request ID (read from context).
func SlogLogger(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		sr := &statusRecorder{ResponseWriter: w, status: http.StatusOK}
		next.ServeHTTP(sr, r)
		slog.Info("http request",
			slog.String("method", r.Method),
			slog.String("path", r.URL.Path),
			slog.Int("status", sr.status),
			slog.Int64("duration_ms", time.Since(start).Milliseconds()),
			slog.String("request_id", GetRequestID(r.Context())),
		)
	})
}
```

package main

import (
	"log/slog"
	"net/http"
	"os"

	"habbits/internal/server"
)

func main() {
	slog.SetDefault(slog.New(slog.NewJSONHandler(os.Stderr, nil)))

	port := os.Getenv("PORT")
	if port == "" {
		port = "8080"
	}

	addr := ":" + port
	slog.Info("server starting", slog.String("addr", addr))

	if err := http.ListenAndServe(addr, server.NewHandler()); err != nil {
		slog.Error("server stopped", slog.Any("err", err))
		os.Exit(1)
	}
}

### Task 10: GitHub Actions workflow

**Files:**
- Create: `.github/workflows/ci.yml`

Two jobs in one file: `test` (on PR, runs `go test`) and `deploy` (on push to `main`, runs `flyctl deploy --remote-only`).

- [ ] **Step 1: Create `.github/workflows/ci.yml`**

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.23'
          cache: true
      - run: go test ./...

  deploy:
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    needs: test
    runs-on: ubuntu-latest
    concurrency: deploy-main
    steps:
      - uses: actions/checkout@v4
      - uses: superfly/flyctl-actions/setup-flyctl@master
      - run: flyctl deploy --remote-only
        env:
          FLY_API_TOKEN: ${{ secrets.FLY_API_TOKEN }}
```

Notes on choices:
- `concurrency: deploy-main` prevents two deploys racing if pushes land back-to-back.
- `permissions: contents: read` is the minimum needed; tighter than the default.
- `go-version: '1.23'` matches the project's `go.mod` minor.
- `flyctl deploy --remote-only` builds on Fly's builders rather than the GHA runner, avoiding Docker setup in CI.
