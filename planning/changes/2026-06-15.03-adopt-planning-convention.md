# Design: Adopt the portable planning convention + migrate docs

## Summary

Replace the ad-hoc `docs/superpowers/{specs,plans}/` layout with the portable
"modern-python" planning convention used across the `pypi/*` repos: a
`planning/` directory holding a conventions `README.md`, `_templates/`, and
per-change bundles under `changes/{active,archive}/`, plus a `deferred.md`
register. Migrate the 9 already-shipped specs+plans into archived change
bundles, record this adoption as the inaugural bundle, add a project
`CLAUDE.md` pointing the workflow at `planning/`, and relocate the legacy BMAD
briefs. This is a **documentation reorganization** — no application code
changes. The `architecture/` truth-home capability docs are deliberately
deferred (the "lighter" adoption).

## Motivation

The repo accumulated 9 spec/plan pairs in `docs/superpowers/`, a flat layout
that separates a change's spec from its plan (different directories), carries
no frontmatter, has no index, and no register for deferred work. The `pypi/*`
projects already use a richer, portable convention that keeps a change's design
and plan together, tracks status/PR/outcome, and maintains an index — and the
goal is one consistent workflow across all repos. Adopting it here also gives
us a real home for the backlog of deferred items this project has accumulated.

## Non-goals

- **`architecture/` truth-home capability docs** — deferred to a follow-up (the
  "lighter" adoption). Recorded in `deferred.md` with a revisit trigger.
- **Rewriting any spec/plan content** — bodies move verbatim; only frontmatter
  is added and files are relocated/renamed.
- **README / LICENSE / CI / Justfile** — separate sub-projects, sequenced after
  this one (they will be authored as new change bundles in the new structure).
- **Application code** — zero `lib/`/`test/` changes; the 115-test suite is
  untouched.

## Design

`docs/superpowers/` is deleted after migration; `docs/` is removed if it ends
up empty.

### 2. Templates + README

- `_templates/{design.md,plan.md,change.md}` copied verbatim from the pypi
  convention, with ONE edit: the `plan.md` template's `Co-Authored-By` trailer
  uses `Claude Opus 4.8 (1M context) <noreply@anthropic.com>` to match this
  repo's commit trailers.
- `planning/README.md` = the **portable Conventions section** (two axes, change
  bundles, three lanes, artifacts-at-a-glance, frontmatter — same wording as the
  pypi repos so it stays portable) **+ a repo-specific Index**. Index has an
  **Active** list (empty after this change ships) and an **Archived (shipped)**
  list of the 10 bundles, newest first, each line linking to its `design.md`
  with `(pr, date) — one-line outcome`. The convention text references
  `architecture/` as the eventual truth home and notes it is forthcoming (see
  `deferred.md`).

**Frontmatter added on migration:**
- `design.md`: `status: shipped`, `date: <change date>`, `slug: <slug>`,
  `supersedes: null`, `superseded_by: null`, `pr: <ref>`, `outcome: <one line>`.
- `plan.md`: `status: shipped`, `date`, `slug`, `spec: <slug>`, `pr: <ref>`.

**`pr` / `outcome` sources** (filled from git during execution):
- reorder-habits → `pr: 2c197d1` (local merge); russian-language → `aff47ab`;
  architecture-refactor → `86f0a38`; app-icon-branding → `#1` / `bbb0a93`.
- foundation, heatmap-retroactive-editing, usability-v2, export-import,
  reminders → `pr: merged to main locally` (these predate the branch/PR
  workflow); the executor records a representative merge/commit where one
  exists.
- `outcome` is a single factual sentence per change (what shipped), written by
  the executor from the spec's own summary — not new analysis.

### 4. `deferred.md`

Seeded from the real backlog, each item a one-line description + a **revisit
trigger**:

- **`architecture/` truth-home capability docs** — *revisit when* the next
  feature change needs a stable capability contract to point at, or on the next
  docs pass.
- **Android notification channel name not localized** (`_channelName = 'Habit
  reminders'`) — *revisit when* notification copy is next touched.
- **`share_plus` iPad popover anchor** (`sharePositionOrigin`) — iPad share
  crash — *revisit when* iPad becomes a target.
- **`TextEditingController` not disposed** in `habit_dialogs` — *revisit when*
  the dialogs move to a `StatefulWidget` or on a lint sweep.
- **Backup test-file naming inversion** (`backup_test` ↔ `backup_codec_test`) —
  *revisit when* either file is next edited.
- **`test/ui/` screen/widget tests not mirrored** into feature subfolders —
  *revisit on* the next test-organization pass.
- **Codecov coverage upload** — *revisit when* the CI sub-project lands (it may
  fold this in).

### 5. Bootstrap, `CLAUDE.md`, legacy, cleanup

- **Bootstrap:** this change's `design.md` (this file) and `plan.md` live in
  `changes/2026-06-15.03-adopt-planning-convention.md`. On merge the bundle
  moves to `changes/` with `status: shipped` and `pr`/`outcome` filled,
  and its Index line moves from Active to Archived — the first real use of the
  convention.
- **Project `CLAUDE.md`** (new, repo root): a short file pointing the workflow
  at `planning/` — "design+plan changes live in `planning/changes/`; see
  `planning/README.md` for the convention." Notes the `architecture/` truth home
  is forthcoming. It supplements (does not replace) the user's global CLAUDE.md.
- **Legacy:** `git mv docs/bmad-legacy/` → `planning/legacy/` (the pre-history
  BMAD product briefs, kept for provenance).
- **Cleanup:** delete `docs/superpowers/`; remove `docs/` if empty.

## Operations

None — no out-of-repo or infra steps. Pure in-repo file reorganization.

## Testing

Structural verification only (this change touches no application code):

- Every one of the 9 old spec/plan files has exactly one new home; no file is
  orphaned or lost (`git mv`/move accounting; `docs/superpowers/` is empty then
  removed).
- Each archived `design.md`/`plan.md` has valid frontmatter with the required
  keys.
- `planning/README.md` Index links resolve to existing `design.md` files (no
  broken relative links).
- `docs/bmad-legacy/` is gone; `planning/legacy/` has its files.
- `flutter analyze` clean and `flutter test` = 115 passing (unchanged — no
  `lib/`/`test/` edits), confirming the reorg touched no code.

## Risk

- **Low overall** — documentation move, fully reversible via git, no code paths.
- **Broken links / wrong frontmatter** (most likely, low impact): mitigated by
  the link-resolution and frontmatter checks in Testing, and by moving bodies
  verbatim.
- **Lost file during the move** (low likelihood, medium impact): mitigated by
  reconciling the count (9 specs + 9 plans in, 9 bundles × 2 out + this change)
  and confirming `docs/superpowers/` is empty before deleting it.
